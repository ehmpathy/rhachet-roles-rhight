# hazard.stored-value-if-deposits-or-transfer

## .what

this is the **boundary map**. an earned, closed-loop, non-transferable reward point sits outside
stored-value / prepaid-access and money-transmission law on those facts (see the CONDITIONAL
money-transmitter brief). these four attributes each place a reward instrument on the **regulated**
side — as **regulated stored value or money transmission**:

- **(a) a point sold / loaded / deposited** — funds are accepted in advance
- **(b) a point transferable to a third party** — value moves person-to-person
- **(c) an open-loop redemption** — a point spends as cash anywhere or at other merchants
- **(d) an actor holds a customer's funds and forwards them to a third party** — the two-element
  transmitter test closes

each attribute is paired below with the authority that makes it bite. while none of the four is present
(the instrument stays earned, non-transferable, closed-loop, with no custody) the regime does not
attach; where any one is present, it attaches.

## .why

- the analysis rests on **facts about the point**, not on a label. a disclaimer does not save an
  instrument that **accepts funds in advance** or **moves value to a third party**.
- prepaid access turns on **"paid in advance"** — change (a) supplies exactly that.
- money transmission turns on **accept-from-one + transmit-to-another** — changes (b), (c), (d) supply
  the transmission element an earned point lacks.
- the closed-loop exclusion holds only while redemption stays **inside** the program — change (c) breaks
  it.

> **not legal advice.** informational groundwork for counsel to validate.

## trigger (a) — a point sold / loaded / deposited → prepaid access

an earned point has no sum paid in advance. prepaid access is defined precisely around value that
**has been paid in advance**:

> "Access to funds or the value of funds that have been paid in advance and can be retrieved or
> transferred at some point in the future"

**source**: [31 CFR § 1010.100(ww)](https://www.law.cornell.edu/cfr/text/31/1010.100)

the state definition is the mirror image — a claim against the issuer that is monetary value, which a
sold or loaded balance becomes the moment a buyer funds it:

> "'Stored value' means monetary value representing a claim, against the issuer, that is evidenced by
> an electronic or digital record and that is intended and accepted for use as a means of redemption
> for money or monetary value, or payment for goods or services."

**source**: [Ind. Code § 28-8-4.1-201](https://codes.findlaw.com/in/title-28-financial-institutions/in-code-sect-28-8-4-1-201/)

the IN loyalty carve-out survives **only** while the value is "not sold to the public." a **sold** or
**loaded** point defeats its own carve-out, because carve-out (C) is limited to value "not sold to the
public but issued and distributed as part of a loyalty, rewards, or promotional program." sell it and
(C) no longer applies.

> **the line**: a point stays outside where it is **earned only** — never bought, loaded, topped up, or
> deposited; a sold or loaded point crosses in.

---

## trigger (b) — a point transferable to a third party → money transmission

a non-transferable point never moves person-to-person. where a holder can send a point to another
person, the transfer of value **to another person** is present — the second element of the transmitter
test:

> "acceptance of currency, funds, or other value that substitutes for currency from one person and
> the transmission of currency, funds, or other value that substitutes for currency to another
> location or person by any means"

**source**: [31 CFR § 1010.100(ff)(5)](https://www.law.cornell.edu/cfr/text/31/1010.100)

a point-to-person transfer also drops the value out of the IN closed-loop and loyalty carve-outs,
which model-act adoptions confine to value that stays with the issuer. the model text — as adopted —
frames the loyalty/closed-loop exclusion around value **not sold to the public** and redeemable with
the issuer:

> "Notwithstanding the foregoing, stored value does not include a payment instrument or closed loop
> stored value, or stored value not sold to the public but issued and distributed as part of a
> loyalty, rewards, or promotional program."

**source**: [Michigan HB 5798 (money transmission modernization act), § 5](https://legislature.mi.gov/documents/2023-2024/billintroduced/House/htm/2024-HIB-5798.htm)

> **the line**: a **non-transferable** point — one that cannot be bought, sold, gifted, or sent
> person-to-person — stays outside; a transferable point crosses in.

---

## trigger (c) — open-loop redemption → stored value + money transmission

a closed-loop consumer point buys only an in-program purchase. closed-loop prepaid access is carved out
precisely because it can be used **only** with a defined merchant:

> "Prepaid access to funds or the value of funds that can be used only for goods or services in
> transactions involving a defined merchant or location"

**source**: [31 CFR § 1010.100(kkk)](https://www.law.cornell.edu/cfr/text/31/1010.100)

the closed-loop shield is not unlimited even where it applies — practitioner analysis of the FinCEN
rule notes the exclusion caps daily value:

> "It provides closed loop prepaid access to funds not to exceed $2,000 maximum value that can be
> associated with a prepaid access device or vehicle on any day"

**source**: [McDermott — FinCEN issues final rules and interpretive guidance relating to prepaid access](https://www.mcdermottlaw.com/insights/fincen-issues-final-rules-and-interpretive-guidance-relating-to)

flip the redemption to **open-loop** — a point that spends as cash anywhere or at unaffiliated
merchants — and both the closed-loop carve-out and the loyalty label fall away. a stricter state
sharpens this edge — florida is an example: its stored-value definition is broad and explicitly reaches
value that is **transferable**, with **no** express loyalty carve-out:

> "currency or monetary value represented in digital electronic format, regardless of whether it is
> specially encrypted, and stored or capable of storage on electronic media in such a way as to be
> retrievable and transferred electronically"

**source**: [Fla. Stat. § 560.103(35)](https://www.flsenate.gov/Laws/Statutes/2025/560.103)

> **the line**: **closed-loop** consumer redemption — a point buys an in-program purchase, never cash, never
> spend at other merchants — stays outside; open-loop redemption crosses in.

---

## trigger (d) — an actor holds a customer's funds and forwards them → money transmission

an own-debt paydown never holds a customer's money for transfer — an earned cash-out is **the issuer's
own revenue** that settles a payable it **owes** for a service, not a customer's funds routed onward.
where an actor instead **receives** a customer's funds and **forwards** them to a third party, it
becomes the statutory **intermediary**:

> "which receives currency, monetary value, a payment instrument, or virtual currency for the purpose
> of acting as an intermediary to transmit currency, monetary value, a payment instrument, or virtual
> currency from one person to another location or person by any means"

**source**: [Fla. Stat. § 560.103(24)](https://www.flsenate.gov/Laws/Statutes/2025/560.103)

the federal registration statute reaches the same conduct — a business in the transmission of value
that substitutes for currency:

> "any other person who engages as a business in the transmission of currency, funds, or value that
> substitutes for currency"

**source**: [31 U.S.C. § 5330(d)(1)](https://www.law.cornell.edu/uscode/text/31/5330)

> **the line**: an actor that **holds no customer funds for onward transfer** stays outside — an earned
> cash-out that comes from an actor's own revenue toward its own booked debt is not a transfer; where an
> actor custodies and forwards a customer's funds, it crosses in.

## the change-trigger table

| trigger | the change | element it supplies | authority that makes it bite | regime |
|---------|-----------|---------------------|------------------------------|--------|
| (a) | point sold / loaded / deposited | "paid in advance"; value "sold to the public" | 31 CFR § 1010.100(ww); Ind. Code § 28-8-4.1-201 | prepaid access / stored value |
| (b) | point transferable to a third party | transmit-to-another | 31 CFR § 1010.100(ff)(5); MTMA § 5 | money transmission |
| (c) | open-loop redemption (cash / other merchants) | breaks closed-loop; breaks loyalty label | 31 CFR § 1010.100(kkk); Fla. Stat. § 560.103(35) | stored value + transmission |
| (d) | holds a customer's funds, forwards to a third party | accept-from-one + transmit-to-another | Fla. Stat. § 560.103(24); 31 U.S.C. § 5330 | money transmission |

## severity

**conditional** — dormant while the four traits hold, **blocker** the moment any one changes. a single
change is enough: each trigger independently supplies the statutory element an earned, closed-loop,
non-transferable point lacks.

florida makes the downside concrete — unlicensed money-services activity there is a **felony** scaled
by value (third-degree at $300–$19,999, up to first-degree at $100,000+):

> "A person may not engage in the business of a money services business or deferred presentment
> provider in this state unless the person is licensed or exempted from licensure under this chapter."

**source**: [Fla. Stat. § 560.125](https://www.flsenate.gov/Laws/Statutes/2025/560.125)

state adoptions of the model act also diverge on exactly these carve-outs, so a shift onto the
regulated side may bite differently across states — "managing compliance with money transmission laws
generally remains a state-by-state proposition."

**source**: [Cooley — US states adopt model money transmission act, but harmonization remains elusive](https://www.cooley.com/news/insight/2024/2024-08-20-us-states-adopt-model-money-transmission-act-but-harmonization-remains-elusive)

## the honest gap

no court has ruled on any specific program, so the change analysis is a **text-level** map of each
trigger onto its statutory element — strong but counsel-confirmable. two soft edges:

- **partial changes.** a program need not trip all four triggers; **one** is enough. a point that is
  earned and closed-loop but quietly **transferable** still supplies the transmit-to-another element.
- **the $2,000 cap and other thresholds.** even a closed-loop program has federal velocity limits, and
  state thresholds differ — so "closed-loop" is a necessary condition, not a blanket exemption at any
  scale.

## key takeaways

| question | answer |
|----------|--------|
| what does this brief do? | it is the **boundary map** of the attributes that attach the regime |
| trigger (a)? | a point sold / loaded / deposited → "paid in advance" → prepaid access |
| trigger (b)? | a point transferable to a third party → transmit-to-another → money transmission |
| trigger (c)? | open-loop redemption as cash / other merchants → breaks closed-loop + loyalty label |
| trigger (d)? | an actor holds a customer's funds and forwards them → intermediary → money transmission |
| how many changes to attach? | **one** — each supplies the statutory element an earned/closed-loop point lacks |
| the four traits that keep it outside? | earned-only; non-transferable; closed-loop consumer redemption; no custody of customer funds |
