# 🌙 dream: a PII commit forced past the hook with --no-verify is caught before it leaves the box

- kind: defect (documented limit)
- owner: rhight / transcriber pii gate
- caught 2026-10-27

## .the cue that fired
`check.pii.guarantee` `[case5]` asserts that `git commit --no-verify` over a staged SSN commits. the catalog holds it as row R5 (D20 = skipped), flagged to the wisher.

## .the gap, precisely
git's `--no-verify` skips every pre-commit hook, so the gate never runs and the value lands in a commit object. the only later layer is CI, after a push has already shipped the value to the remote.

## .the shape of the fix
- a `pre-push` hook that runs the same scan over `origin/main..HEAD` (the commits about to leave), so a bypassed commit is caught before it reaches the remote; `--no-verify` on push stays a deliberate second act
- the CI backstop stays as the last layer; name it in the hook's help so a committer knows where the next check sits
- move `[case5]` from "it commits" to "the push is refused", with a clamp that goes red when the pre-push hook is removed

## .why it is not done in this round
the wish (#52) is the verdict read from `output.response.json`. a pre-push gate is a new hook with its own contract, scope, and tests; it ripples past this diff.
