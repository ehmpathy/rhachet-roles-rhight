# 🌙 dream: a gitignored path can turn a local suite red that CI holds green

kind: fix · owner: repo (test config) · caught 2026-10-26

## .the cue that fired
at head `9e0e66f`, CI was 0 red of 17, yet two local `git.repo.test` tiers exited non-zero for reasons absent in CI:

- **integration:** `FAIL .temp/issue49/transcribe.pdf.integration.test.ts — Test suite failed to run` (40 of 41 suites passed). a parked copy of the #49 work sat under the gitignored `.temp/`, and jest collected it
- **lint:** `npx depcheck` reported `Missing dependencies · claude-code: ./.agent/.actors/actor.via.repo=ambient/brain/.claude/plugins/…/tests/hostile.test.ts`. that is a gitignored per-actor brain cache (`.agent/.actors/.gitignore`: `*`)

## .the gap, precisely
the test config excludes some gitignored dirs and not others. the exclusions are a hand-kept allowlist, so each new scratch dir is a fresh hole.

| config | excludes today | misses |
|---|---|---|
| `jest.integration.config.ts` `testMatch` | `.yalc`, `.scratch`, `.agent/.actors` | `.temp`, and every other gitignored dir |
| `.depcheckrc.yml` | package names only; no `ignore-patterns` | `.agent/.actors`, `.temp`, `.scratch` |

- check `jest.unit.config.ts` and `jest.acceptance.config.ts` for the same gap; only integration was observed
- the failure mode is a false red. it costs a human turn ("green locally reads red"), and it teaches the team to ignore a red local run, which hides a real one

## .the shape of the fix
1. jest, each config: add `'!**/.temp/**'` beside `.scratch`. better: derive one exclusion list from the gitignored dot-dirs, shared by every jest config, so a new scratch dir cannot reopen the hole
2. depcheck: add `ignore-patterns` to `.depcheckrc.yml` for `.agent/.actors`, `.temp`, `.scratch`, `.yalc`
3. clamp: a hermetic test drops a failing `*.integration.test.ts` under `.temp/x/` and a bogus `require('nonexistent-pkg')` under `.agent/.actors/x/`, then asserts each suite stays green. revert the config and it must go red (`rule.require.clamp-edge-cases`)

## .why it is not done in this round
the order was a local log that exits 0 at `9e0e66f` **with no commit**, and #41 is frozen for commander review. the fix is safe and clean (two config files plus a clamp), but it needs a commit on a branch other than #41.

meanwhile, for a clean local run: the #49 copy is renamed to `.temp/issue49/transcribe.pdf.integration.test.ts.parked`. it is byte-identical to HEAD plus `.temp/issue49/issue49.temp-dir-mask.patch`, which stays in place. the `.agent/.actors` plugin is not this driver's to remove, so local lint stays red until fix 2 lands.
