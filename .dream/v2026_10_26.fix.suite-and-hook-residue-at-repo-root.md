# 🌙 dream: a test and a hook leave unignored residue at the repo root

kind: fix · owner: repo (tests, pii hook) · caught 2026-10-26

## .the cue that fired
a release inventory of the paths the PR lacks found two that no human wrote:

- `tsconfig.probe.json`: `src/publish.set.integration.test.ts` writes it to the repo root (`path.join(root, 'tsconfig.probe.json')`) to probe the build's file set, and never removes it. every integration run recreates it
- `.pii-review.anthropic-claude-opus.md`: the pre-commit pii.review writes its report to the repo root on every commit attempt

neither path is gitignored, so each shows as `??` in every status and invites a stray `git add .`

## .the shape of the fix
1. publish.set test: write the probe into `genTempDir` (or remove it in an `afterAll`). the probe's `include` is relative, so set `compilerOptions.rootDir` / absolute globs, or copy the build config beside it
2. pii.review: write the report under `.log/` (as `rhx review` does), or add `.pii-review.*.md` to `.gitignore`
3. clamp: after the publish.set suite, assert no `tsconfig.probe.json` remains at the root

## .why it is not done in this round
the order was an inventory and a fresh test run with no commit, and the quota is spent.
