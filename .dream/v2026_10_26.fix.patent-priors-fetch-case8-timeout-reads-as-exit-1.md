# 🌙 dream: patent.priors.fetch case8 times out under load, and the timeout reads as exit 1

kind: fix · owner: patenter · caught 2026-10-26

## .the cue that fired
a full local integration run at `9e0e66f` (log `.log/role=mechanic/skill=git.repo.test/what=integration/2026-10-26T05-05-03Z.stderr.log`) failed one test:

```
✕ [case8] deterministic cached flow (uses fixture) › all documents report cached status (no API calls) (32831 ms)
  expect(result.exitCode).toBe(0) · Received: 1
```

the same case passed 3 of 3 in isolation minutes later, in CI at `9e0e66f`, and in the prior full local run.

## .the gap, precisely
1. **the budget is too tight for a parallel run.** case8 passes `timeout: 30000` ("30s is plenty for cached flow"). under `maxWorkers: '50%'` beside the 500s `pii.scan.repo` suite, it ran 32.8s and spawnSync killed the child
2. **the kill is disguised as a skill failure.** `runFetch` maps `exitCode: result.status ?? 1`. a killed child has `status === null` and `signal === 'SIGTERM'`, so a timeout surfaces as `Received: 1`, which is indistinguishable from the skill's own malfunction exit. that sends the next reader to debug the skill rather than the budget

## .the shape of the fix
1. surface the kill: return `signal` from `runFetch` and fail loud on it, e.g. `if (result.signal) throw new Error(\`spawn killed by ${result.signal} after timeout ${timeout}ms\`)`. the same `status ?? 1` shape likely sits in `patent.priors.search` and the transcriber harnesses, so sweep them
2. widen case8's budget to a value that holds under a full parallel run (e.g. 120s). the assertion that matters is "no API calls", which `retrieval: cached` already proves, never the wall clock
3. clamp: a hermetic case runs the harness against a stub that sleeps past a tiny timeout, and asserts the error names the signal rather than reporting exit 1

## .why it is not done in this round
the order was a local log that exits 0 at `9e0e66f` with no commit, and #41 is frozen for commander review. the fix is safe and clean (two test files) but needs a commit off #41. the flake is proven (a timeout, not a logic fault), so a rerun is a legitimate retry for the local log.
