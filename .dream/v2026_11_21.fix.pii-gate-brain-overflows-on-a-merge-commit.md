# 🌙 dream: the pii brain gate cannot review a merge commit of real size

kind: fix · owner: transcriber (pii.scan.via.brain) · caught 2026-11-21

## .the cue that fired
a merge of main (#54) into #41 was refused: "prompt exceeds 75% of context window", 94.1% of 200,000 tokens on haiku. the gate's own fix ("split them into separate commits") cannot apply to a merge commit, which is one commit by definition.

## .the gap, precisely
- the brain pass sends the whole staged set in one `rhx review` call
- a merge commit's staged set is everything the other parent brought in; here 508k chars under `src/domain.roles/transcriber` alone (~66% of the window)
- the only way through was to pre-commit main's files as normal commits ahead of the merge, which costs commit quota per chunk

## .the shape of the fix
review the staged set in batches sized under the window (by bytes, per file), and union the verdicts; any blocker from any batch blocks. #41 carried this (`as_batch_glob`, `PII_REVIEW_BATCH_BYTES`) before the merge took main's gate whole; reapply it over #54's json verdict read, one `rhx review` per batch.

## .why it is not done in this round
the round's outcome is #41 mergeable with its own behavior only; a new gate feature over #54's design is a change of its own, and the pr41 merge is mid-flight on quota.
