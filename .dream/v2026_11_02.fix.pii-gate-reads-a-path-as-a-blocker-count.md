# 🌙 dream: the pii gate reads a staged path as a blocker count

kind: fix · owner: transcriber (pii.scan.via.brain) · caught 2026-11-02

## .the cue that fired
a commit that staged `.route/v2026_10_23.pr41-green/blocker/5.briefs.short.md` was blocked with
`🚨 anthropic/claude/opus — 5 blocker(s)`. the brain answered `"blockers": []` both times, and the
reviewer's own summary line read `0 blockers`.

## .the gap, precisely
`pii.scan.via.brain.sh:467` takes the FIRST match of
`([0-9]+)[^0-9a-z]{0,6}blockers?|blockers?[^0-9a-z]{0,6}([0-9]+)` in the reviewer's whole stdout.
that stdout echoes the scope paths before the summary, so `blocker/5` (line 9) wins over
`0 blockers` (line 51). any staged path with a `blocker` segment and a digit after it fakes a count.

## .the shape of the fix
1. parse only the summary block, the last `N blockers` / `N nitpicks` pair after the `logs:` line,
   or read `output.response.json` from the advertised log dir, never the echoed scope
2. clamp: in the mock describe of `pii.scan.via.brain.live.integration.test.ts`, have the mock echo
   a `paths:` line holding `blocker/5.x.md` ahead of `0 blockers`; assert exit 0. revert the fix → red

## .why it is not done in this round
the gate is a tier 1 safety guard; a change to its parse in #41 is a change to the gate that
approves #41. the director routes gate changes to their owner. the blocker route file stays
uncommitted until this lands.
