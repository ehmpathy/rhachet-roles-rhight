# 🌙 dream: `rhx upgrade` writes a machine home path into a tracked settings file

kind: reseed · owner: rhachet (the actor-layout migration) · caught 2026-10-27

## .the cue that fired

a 5.1 peer review found `"/home/<user>/.claude/CLAUDE.md"` in `.agent/.actors/actor.via.repo=ambient/brain/.claude/settings.of.repo.json`, a tracked file the boot repair produced. `origin/main` held no such path.

## .the gap, precisely

`getClaudeMdExcludesList` (`rhachet/dist/domain.operations/enroll/getClaudeMdExcludesList.js`) lists the human's user door as `join(input.home, '.claude', 'CLAUDE.md')`, an absolute literal, and the boot sync writes that list into the repo actor's `settings.of.repo.json`, which every clone tracks. its own note says that file "must hold no per-worktree path", and globs the local door for that reason; the home door is the one literal left. it returns on every install, so a downstream hand-edit cannot hold.

## .the shape of the fix

write per-machine excludes to the untracked layer (or a `~`-relative form the reader expands), never to `settings.of.repo.json`. a test: run the migration under a temp HOME and assert the tracked file holds no HOME prefix.

## .why it is not done in this round

the fix lives in rhachet, another repo. this route dropped the one line (fulcrum F9).
