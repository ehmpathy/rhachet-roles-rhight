# 🌙 dream: a binary that carries PII is read, not just named, before it commits

- kind: defect (documented limit)
- owner: rhight / transcriber pii gate
- caught 2026-10-27

## .the cue that fired
`check.pii.guarantee` `[case6]` asserts that a staged PNG whose bytes carry an SSN commits on the default path, with no bypass. the catalog holds it as row R6 (D21 = binary), flagged to the wisher.

## .the gap, precisely
the regex pass reads text only: it skips a binary and prints `skipped … binary … NOT scanned`. the brain is handed binary paths by name, never their content. when the brain answers clean, the binary commits. the 2026-08-31 PNG was this exact case.

## .the shape of the fix
- extract text from staged binaries before the regex pass: `strings`-style printable runs for any binary, and `transcribe.pdf` (this role's OCR skill) for images and scanned PDFs, then scan the extracted text
- a binary whose text cannot be extracted blocks, or asks for an explicit allow, rather than passing with a skip line
- move `[case6]` from "it commits" to "it blocks", with a clamp that goes red when extraction is removed

## .why it is not done in this round
the wish (#52) is the verdict read from `output.response.json`. binary extraction is a new input path, with OCR cost, credentials, and false-positive tuning; it ripples past this diff.
