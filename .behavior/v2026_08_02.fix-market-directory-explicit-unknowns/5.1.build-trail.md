## .what this file is for

the route carries a persistent instruction: *"record findings inline rather than absorb them
silently."* that instruction is **right** — an agent that quietly edits away its own error destroys
the evidence, so the error recurs and no reviewer can audit the fix.

⛔ **and it had no destination**, so ~76 correction blocks landed inside 16 **shipped** briefs under
`src/domain.roles/counselor/briefs/market/directory/`, where
`rule.forbid.aggregation-index-build-narrative` forbids them.

**this file is the destination.** every construction record goes here; the shipped brief keeps the
corrected state and no history.

## ⭐⭐ .why this file is NOT `5.1.restricted.applied-design.md`

a reviewer caught this before the sweep ran, and the catch prevented a re-do:

> *"If the sweep dumps ~76 blocks into `5.1.restricted.applied-design.md`, that file becomes a fusion
> of two unrelated concerns — the identical 'decompose for recompose' defect this entire review chain
> exists to catch in `hazard._.catalogue`, just recurring one level up, at route grain instead of
> brief grain."*

⭐ **the two artifacts are governed by different rules, for different audiences, and hold different
kinds of record.** they are not two flavours of "the private file":

| | `5.1.restricted.applied-design.md` | **this file** |
|---|---|---|
| governed by | `rule.require.fullsun-facts-not-tactics` | `rule.forbid.aggregation-index-build-narrative` |
| holds | applied design, weak-spot assessment, fingerprint content | construction history — counts, drift, corrections |
| audience | an **implementer** | a **reviewer of the work** |
| verdict | 🔒 **protect** — a leak is adversarially useful | 🕶️ **obscure** — a leak is merely noise |
| lifecycle | outlives the route; hands to the client | dies with the route |

> ⛔ **to have merged them would have been the same defect the whole review chain exists to catch,
> one grain up.** the catalogue fused law + build narrative + applied design; a merged private file
> would fuse design + build narrative. **the fix for a fusion is never a different fusion.**

## .what goes here — the test

> would a reader who wants a brief's **subject** care about this paragraph?

- **no, it is about how the file got here** → here
- **yes, it changes what the reader should believe** → it stays in the brief

⚠️ **the discriminator is the AUDIENCE, not the severity.** a retraction of a superseded rule stays
in the brief — a reader who misses it applies a rule we withdrew. a count correction comes here.

## ⭐⭐ the sweep result

**run 2026-08-03 across all 16 files.**

### ⛔⛔ the verification I FIRST recorded here was worthless, twice over

**corrected in place, because the defect is the exact shape this file exists to record.** the command
originally written here as proof was:

```
npx rhachet run --skill grepsafe --pattern '…' \
  --glob 'src/domain.roles/counselor/briefs/market/directory/**/*.md'   ← ⛔ ALWAYS 0
```

⛔ **`grepsafe --glob` matches on BASENAME, not on a path.** `--glob '*.md'` works; a path-shaped
glob matches no file and returns `0 matches` **whatever the pattern is**. so the command recorded as
the sweep's proof was **vacuously true** — it could not have found a defect even if the sweep had
never run.

⛔ **and the pattern was ALSO incomplete**, which an l3 reviewer found: six shipped briefs carried a
*"gerund hook retried deliberately"* preamble — pure construction history, in a fullsun brief, at
**line 3** — and the pattern did not name that string. **the reviewer's phrasing is the one to keep:
"the build-trail's own verification grep doesn't match this phrasing, so it reported 0 matches and
re-tagged the cluster clean while this leak was outside its pattern."**

> ⭐⭐ **two independent failures, and either alone would have produced the same false green.** a
> broken glob (matches no file, ever) and a short pattern (finds only what you already thought of).
> **the first is invisible because 0 is the answer you want; the second is invisible because you
> wrote the pattern from memory of your own edits.**
>
> ⛔ **this is lesson 1 in the table below, recurring on the pass that recorded lesson 1.** *"a count
> is only as good as its least-examined input"* — and a **verification command** is the least-examined
> input of all, because a clean result is read as evidence rather than as a claim.

**the corrected verification, run with the Grep tool over the directory (no glob involved):**

```
'corrected in place|RETRACTED|DOWNGRADED|gerund hook|an l3 reviewer|the reviewer was|
 this session|this route|route refs/|5\.1\.restricted|\.behavior/|genuinely mine'
→ 0 matches across 0 files
```

⭐ **the pattern is wider than the first on purpose.** it now catches four classes the first missed:
the gerund-hook preambles, *"an l3 reviewer"* attributions, **route-time referents** (*"this
session"*, *"this route"*), and **pointers into route-private directories**.

⚠️ **the route-private pointers were a real leak of a second kind.** the pre-sweep catalogue named
`.behavior/…/5.1.restricted.applied-design.md` in two relocation notices I wrote in good faith, and
eleven briefs pointed at *"the route's refs/"*. **a public brief that names a private artifact's
path tells a reader it exists and what it is called** — created by the redaction itself.

⚠️ **that second one mattered.** the pre-sweep state had the catalogue point a ☀️ fullsun brief at
`.behavior/…/5.1.restricted.applied-design.md` in two places — relocation notices written in good
faith. **a public brief that names the path of a restricted artifact is a leak of a different kind:**
it tells a reader that a private design document exists and what it is called. the notices are gone.

### what the sweep did NOT delete, and why the distinction held

each of these looked like build narrative by its header and was **content** by its audience:

| kept | why |
|---|---|
| the `G-<slug>` gap rows, all 17 | open legal exposures — they change what a reader should believe |
| *"expiry beats re-check outside the gate and fails inside it"* (stale-record) | a scope boundary on a live argument, not a story about a correction |
| the canonical-atom vs canonical-analysis table (glossary) | a **convention** that explains why § 1681a(c) appears in seven files |
| *"do NOT bound paid placement to person grain"* (asymmetric-disclosure) | the result survived; only the *"three statements had drifted"* narrative left |
| the three below-floor citation notes | a reader who weighs how much to trust a brief needs its true source count |

⭐ **the reshape, not the strip, is the technique.** most blocks were not deleted — they were
**re-cast from a correction announcement into a statement of what is true**. a header that read
*"### ⚠️⚠️ CORRECTED — two states supply a NUMBER"* became *"### ⚠️⚠️ two states supply a NUMBER"*,
and the paragraph beneath it survived intact.

### ⭐ two structural defects the sweep surfaced that no reviewer had caught

1. **a duplicated line** in `hazard.unclaimed-profile-right-of-publicity` — the *"captured via browser
   this session"* sentence appeared twice in `.sources`, once on its own and once inside the
   mirror-fallback note
2. ⛔ **a broken numbered list** in `hazard.stale-public-record-status` — an ordered list ran
   `5 → 9`, because an interleaved correction block had been inserted mid-list and the renumber never
   happened. **the correction blocks were not merely misfiled; one of them had corrupted the
   structure of the content around it.**

> ⭐ **that is the argument for the sweep beyond the publishability rule.** a construction record
> interleaved with content does not sit inertly beside it — it fragments the content's own structure,
> and the fragmentation is invisible until the record is pulled out.
