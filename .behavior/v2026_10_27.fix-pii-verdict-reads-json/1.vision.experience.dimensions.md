# 1.vision.experience.dimensions

the encounter: a committer runs `git commit`, which fires `.husky/pre-commit` → `.husky/check.pii.sh` → `pii.scan.sh` → `pii.scan.via.brain.sh` → `rhx review` once per `--brain`. the experience space is what the gate reads off each review, and what it then decides.

## the dimensions

| # | dimension | positions | why it varies |
|---|-----------|-----------|---------------|
| D0 | **actor** | `human` · `automation` (a clone or crew that commits programmatically, e.g. the registrator crew) | who meets the verdict, and how they recover from it |
| D1 | **logs line** | `present` · `absent` | `rhx review` prints `logs:` on a run; a skip prints none (`getReviewSkipReport.js`), and neither does a run that crashes before its log dir (e.g. no brain key) |
| D2 | **json state** at `<logs>/output.response.json` | `valid` · `absent` · `unparseable` · `non-array` | the file the cure reads; each non-valid position must fail closed |
| D3 | **blockers in the json** | `zero` · `some` (≥1) | the decided verdict |
| D4 | **stdout echo** — the first `blocker…<digit>` token in raw stdout, relative to the json blocker count | `none` (no such token) · `agrees` (digit = count) · `reads-high` (digit > count) · `reads-low` (digit < count) | staged paths, rule names, prose — any text `rhx review` echoes ahead of its summary. this is the token the OLD parse read |
| D5 | **nitpicks in the json** | `zero` · `some` | printed beside the verdict; never decides it |
| D6 | **attempt** | `first` · `retry` | the gate retries once on an unreadable verdict (`pii.scan.via.brain.sh:399`) |
| D7 | **reviewers** | `one` · `many` | `--brain` may repeat; verdicts union in `main` |
| D8 | **concurrency** | `alone` · `alongside` another gate run | two commits at once, in one tree or in two |
| D9 | **scope filter** on the staged paths | `kept` (`--polluters keep`) · `dropped` (the `rhx review` default) | route paperwork, dreams, and lockfiles are dropped from scope unless the gate keeps them; found in execution |
| D10 | **refusal** before any brain call | `none` · `zero-scope` · `overflow` · `credential` · `unlisted` | `rhx review` refuses an empty scope, a prompt over 75% of the window, an absent brain key, or any other cause (e.g. an unknown flag), each with a `ConstraintError:` header and no `logs:` line; zero-scope and overflow found in execution, credential and unlisted in verification |
| D11 | **staged change kind** | `add` · `modify` · `rename` (git `R`, moved and edited) | the file list each scanner builds; a rename fell outside `--diff-filter=ACM`; found in peer review |
| D12 | **hook pass** | `first` · `husky re-run` | husky re-execs `pre-commit`, which sources the gate again; found in peer review |
| D14 | **log retention** after the read | `clean read` · `unread` | the review log dir holds the prompt, which holds the staged diff. a clean read prunes every file but the figures (args, scope, metrics, tokens); an unread verdict keeps them for its cause; found in verification |
| D15 | **prior report** in the tree | `none` · `stale` (a `.pii-review.<slug>.md` a prior block left) | the block copies its report into the tree; it quotes the value it found; found in verification |
| D16 | **cwd** of the run | `repo top` · `subdir` | a commit may run from any dir of the repo; the gate reads paths from the repo top; found in verification |
| D17 | **review focus** handed to `rhx review` | `push` (the diff in the prompt) · `pull` (paths only) | an api brain has no filesystem: under `pull` it grades a diff it never saw and answers `0 blockers`. the gate pins `push`; found in verification (live suite header) |
| D18 | **rules handed** to the reviewer | `refs present` · `refs absent` | an api brain boots none of the role's briefs; with no `--refs` it still answers, parses, exits 0, and grades with no rules on what counts as PII. the gate always passes `--refs`; found in verification (live suite header) |
| D19 | **husky runtime** on the box | `present` · `absent` (`_/husky.sh` gone: a fresh clone that never ran `npm install`) | the gate sits above husky's runtime guard; found in verification (`check.pii.guarantee` `genHuskyWithoutRuntime`) |
| D20 | **hook chain** at commit | `run` · `skipped` (`git commit --no-verify`) | git's own bypass skips every hook; found in verification (`check.pii.guarantee` `[case5]`) |
| D21 | **input type** staged | `text` · `binary` | the regex pass reads text only; found in verification (`check.pii.guarantee` `[case6]`) |
| D13 | **cut paths** in the staged set — a lockfile, or a dir (a dir symlink, a submodule) | `none` · `some` · `all` | `rhx review` never takes these as targets: lockfiles by the gate's `--paths-wout`, dirs upstream; found in peer review |

D4 is defined against the json count, not against a fixed digit, so it is orthogonal to D3 except where arithmetic forbids it: `reads-low` needs a count above zero.

## the walked product — the decided core

D1=present × D2=valid × D3 × D4:

| | none | agrees | reads-high | reads-low |
|---|---|---|---|---|
| **zero** | C1 pass | C2 pass | C3 pass — the defect today | ✗ impossible (no digit below 0) |
| **some** | C4 block | C5 block | C6 block | C7 block — the fail-open today |

7 decided cells, 1 impossible.

## the walked product — the unread verdicts

- **D1=absent** ⇒ D2..D5 unreachable: no `logs:` line names no dir. 1 cell: C11 skip → malfunction.
- **D2 ∈ {absent, unparseable, non-array}** ⇒ D3..D5 unknowable: no readable json, no verdict, and D4 must not stand in for one. 3 cells: C8, C9, C10 → malfunction, each with its own cause line.

total: 7 decided + 4 unread = **11 cells**, + 1 impossible.

## the dimensions that commute — why they are walked by argument, not by product

each has a stated reason it cannot change a cell's outcome; each still gets an inventory row.

- **D0 actor.** the gate decides before any actor reacts, and returns one exit code. the actor changes only the recovery: a human reads the tree and redacts; automation reads the exit code (2 = fix the diff, 1 = fix the tool) and surfaces the same tree in its log. so every cell holds for both actors, and the exit-code split is what makes the automation path workable. row A1.
- **D5 nitpicks.** the gate blocks on `blockers > 0` only (`main`, `:566`). nitpicks are printed (`clean (N nitpick(s))`), never summed into the decision. row N1.
- **D6 attempt.** every unread state retries, the skip (C11) included. a retry re-runs the same read on a fresh review, and the outcome is the outcome of the second attempt: valid → that cell's decided outcome; unread again → malfunction. so the C8–C11 rows state the two-attempt outcome, and an unread first attempt can never pass on its own. rows M1 (retry recovers) and M1b (both attempts unread).
- **D7 reviewers.** each reviewer's verdict is a pure function of its own review (own process, own log dir `<iso-ms>.<pid>.<uuid>`). `main` then folds them in a fixed order: any block → block (exit 2); else any malfunction → malfunction (exit 1); else pass. so a many-reviewer run is the fold of one-reviewer cells. the fold has three outcomes, one row each: M2 any block → block (demoed, the critipath), M2b no block + a malfunction → malfunction, M2c all clean → pass.

- **D8 concurrency.** the VERDICT commutes: each reviewer of each gate run reads its own log dir, named `<iso-ms>.<pid>.<uuid>`, so two runs at once — in one tree or two — can never cross verdicts. the REPORT copy does not fully commute: two gate runs at once in ONE tree, on the same brain, both `cp` to `./.pii-review.<slug>.md`, and the later copy wins. (checked: a plain `git commit` does NOT hold `.git/index.lock` while pre-commit runs, so git does not serialize them.) the outcome and exit code of each run stay right; only the report a human opens may belong to the other run. that copy is extant and outside this wish. row K1.

## the dimensions found downstream — walked by argument

- **D9 scope filter.** `dropped` × a commit of only route paperwork ⇒ `zero-scope` (D10), the commit this wish exists for. the gate pins `kept`, so `dropped` is unreachable from the gate; it stays a row for the refusal it caused. cell C12.
- **D10 refusal.** each refusal prints no `logs:` line, so it lands in D1=absent; a named cause and no retry set it apart from C11. cells C13 (zero-scope), C14 (overflow).
- **D11 change kind.** `rename` was a fail-open: the file list skipped it, so neither layer scanned its new content. `add` and `modify` were always listed. cell C15.
- **D12 hook pass.** the re-run sees the same staged tree and skips; a changed tree rescans. the verdict is the first pass's. row H1.
- **D10 credential, unlisted.** both print a `ConstraintError:` header and no `logs:` line. the gate asks once, names the header as `rhx review refused: <message>`, and fails closed; a credential refusal adds the keyrack hint. cells C17 (credential), C18 (unlisted).
- **D14 log retention.** `clean read` ⇒ the prompt and response leave the disk, across every attempt's dir; `unread` ⇒ all kept, so the cause can be read. commutes with D3: a block is a decided read, so its log dir is pruned too, and its report in the tree carries the finding. cell R1.
- **D15 prior report.** `stale` × a clean read ⇒ the report is removed, so no prior finding lingers past the fix. cell R2.
- **D16 cwd.** `subdir` ⇒ the gate moves to the repo top first, so the staged paths, the rubric, and the refs resolve as from the top. cell R3.
- **D17 focus, D18 rules.** `pull` and `refs absent` each yield a false clean over an ungraded diff: a fail-open. the gate pins `push` and always passes `--refs`, so both are forbidden cells, clamped by `[case16]` (`⭐ it PUSHES the diff`, `⭐ it hands over the role's briefs, as --refs`).
- **D19 husky runtime.** commutes: the gate runs before husky's runtime guard, so `absent` yields the same verdict as `present` — PII blocks at exit 1 from git, clean passes (`check.pii.guarantee` `[case2]`, `[case3]` beside `[case1]`, `[case4]`). row R4.
- **D20 hook chain.** `skipped` ⇒ no hook runs, so a PII commit lands. no hook can close it; the CI backstop is the next layer. a documented limit, outside this wish, asserted rather than assumed. row R5.
- **D21 input type.** `binary` ⇒ the regex pass skips the file and says so (`skipped … binary … NOT scanned`); the brain is handed binary paths by name only. with the brain clean, a binary that carries PII commits on the default path. a documented limit, outside this wish. row R6.
- **D13 cut paths.** the gate splits them off before its empty check and names each one. `all` ⇒ files 0, a pass with no ask; `some` ⇒ the rest is reviewed. without the split, `all` reached `rhx review` empty and blocked as a zero-scope refusal. cells C16, C16b.

## the invariant the product proves

across every cell, **D4 never changes the outcome**: C1/C2/C3 all pass and C4/C5/C6/C7 all block. the verdict is a function of (D1, D2, D3) alone.
