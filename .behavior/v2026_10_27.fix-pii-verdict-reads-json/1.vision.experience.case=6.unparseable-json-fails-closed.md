# case=6 — an unparseable verdict file fails closed (C9 · sharp · critipath)

## narrative

a human commits on a laptop whose disk is nearly full. the commit is refused with `🦅 the review could not run`. the cause line reads `verdict json unparseable at .log/bhrain/review/<ts>/output.response.json`. they open that file and find it cut off mid-array: `{"done": true, "blockers": [`. the review ran, but its verdict was never fully written, so nobody knows what it found. the gate retried once and hit the same full disk. they free space, commit again, and the retry is whole: the json reads clean and the commit lands (row M1). at no point did a half-written verdict let the commit through.
